# فایل‌های همراه پروژه RoboRace

این بسته نمونه فایل و مرجع قرارداد است و شامل پیاده‌سازی پاسخ پروژه نیست.

## محتوا
- scenarios/demo01.race: سناریوی اصلی با صندوق و پل؛ مناسب هر دو فاز.
- scenarios/chest_race.race: دو ربات برای OPEN مشترک در Tick سوم.
- scenarios/bridge_demo.race: رقابت روی پل با ظرفیت یک.
- scenarios/disconnect_demo.race: سناریوی پل برای آزمایش قطع اتصال.
- scenarios/stress10.race: سناریوی ۱۰ ربات هم‌زمان.
- examples/phase1: نمونه کامل تبادل پیام، لاگ و گزارش فاز اول برای demo01.
- examples/phase2_safe: نمونه کامل حالت safe برای chest_race.
- examples/phase2_unsafe: نمونه کامل تخصیص دوباره صندوق و گزارش FAIL.
- CONTRACT_FA.md: قرارداد کامل پیام‌ها، ثبت رویداد، Tick و بررسی صحت.

## نکته‌های استفاده
فایل‌های نمونه را مستقیم به JSON parser بدهید؛ پسوند race محتوای JSON را تغییر نمی‌دهد. messages.jsonl باید خط‌به‌خط خوانده شود و یک آرایه JSON نیست.
رویدادهای events.log و گزارش‌ها نمونه آموزشی هستند؛ آن‌ها را به‌عنوان خروجی اجرای برنامه خود تحویل ندهید. حالت unsafe عمداً دو تخصیص SUCCESS ثبت می‌کند؛ بررسی‌کننده باید single_chest_owner را FAIL بدهد.
دو ربات در نمونه unsafe هر دو مالک خالی را پیش از نوشتن خوانده‌اند؛ ترتیب سریال سطرهای Log به‌معنای سریال‌بودن بررسی اولیه آن‌ها نیست.
برای disconnect_demo، یکی از Robot Clientها را هنگام حضور روی پل با سیگنال قطع کنید؛ به‌عنوان نمونه، پس از مشاهده BRIDGE_ENTER مربوط به R1، فرمان kill -KILL را برای PID همان پردازه اجرا کنید. PID باید از اجرای واقعی گرفته شود. قطع اتصال در فایل سناریو کدنویسی نشده است و باید واقعاً روی TCP رخ دهد.
این نمونه‌ها حداقل‌های قالب‌اند؛ آزمون‌های پل، قطع اتصال و ۱۰ کلاینت باید با کد خود گروه اجرا و لاگ واقعی آن‌ها تولید شوند. اجراهای هم‌زمان ممکن است ترتیب متفاوت ولی معتبر داشته باشند.
